# What RASD Proves That a Rule Repository Cannot

Each row is a claim a detection library usually makes in words, and the tool that turns it into something the build checks. The numbers behind every row are on the [metrics page](RASD_METRICS.md).

| Claim | How RASD proves it |
|---|---|
| The rule catches the attack | True-positive tests, hand-written technique mutations, and an **evasion fuzzer** that generates renamed binaries, forward-slash paths, parameter prefixes, hex/decimal encodings and ordinal exports - against a regression baseline |
| Every part of the rule is needed | **Rule mutation testing** (`rasd prove`): every value, field and branch of every rule is deleted in turn, and a test must fail each time. It found 45% of the original rule logic unproven by any test; today every mutant is killed or accepted as equivalent |
| The SIEM query is the tested rule | **Query parity** (`rasd parity`): the generated KQL and SPL, and the Defender XDR advanced hunting queries where a Defender table exists, are parsed back and run by RASD's own interpreter of each language (null fields, case rules, regular expressions) on thousands of events. It found that Splunk silently dropped events with a missing field under `NOT`; the converter now reads those fields null-safely. Running the queries in a live SIEM is part of the lab evidence still pending |
| The rule logic holds for every possible value, not only for samples | **Exact automata** (`rasd certify`): every rule is compiled into finite automata that accept exactly what the engine accepts, over every Unicode code point rather than a sample of them. From the automata certify builds an event that fires the rule and the nearest event that does not, and replays both through the engine; a rule that could never fire, or could never stay quiet, would be proven so and fail the build. Each value test is checked against the engine on its complete W-method conformance suite ([the mathematics](CERTIFY.md)) |
| The rule catches the attack however it is written | **Behaviour proofs** (`rasd certify`): a detection's `behavior.yml` writes down, from vendor source code and documentation, the ways its technique can appear in the events the rule reads, including how Windows splits a command line into the arguments the program actually receives. Each variant is proven caught for every possible event, or an event that slips past is shown and replayed through the engine. 81 variants over 16 detections are decided this way (counted on every build, in the metrics above); every known gap is listed with its fix, and CI fails on a gap the spec does not list or a listed gap that has quietly closed ([certificates](CERTIFICATES.md)) |
| An edit did not change what a rule catches | **Edit equivalence** (`rasd certify --equiv REF`): the current rule and its version at a git ref are put over one shared set of automata, and the events on which they disagree are searched exhaustively. Either the search is empty, which proves the two versions classify every possible event alike (a rule can be refactored, split or reordered with proof that nothing it catches moved), or it returns the event that now lands on the other side, replayed through the engine against both versions ([how](CERTIFY.md#comparing-two-versions-of-a-rule)) |
| Attacks no single event shows are caught | **Sigma correlation detections** (`rasd correlate`): a password spray, Kerberoasting by volume, API authentication probing and object-ID enumeration, as tested rules rather than hunts. Every threshold, window, group-by and normalisation is held in place by an event-sequence scenario (parameter mutation testing); the generated SPL and KQL aggregations are parsed back and must return the engine's exact alerts for the rule and every mutant; and each carries a **proven burst guarantee**: 2T-1 distinct values in one window length always alert, whatever the window alignment (for the spray, 9 accounts in 10 minutes) |
| You know where false positives will come from | **Near-miss analysis** (`rasd nearmiss`): every event one field edit away from an alert, each proven by a witness the engine confirms, grouped by the condition holding it back; CI fails when a boundary carrying traffic has no true negative pinning it. For correlations, the headroom between the busiest quiet window and the threshold |
| It stays quiet on normal activity | True-negative tests, a filter-coverage gate, and **tuning impact analysis** (`rasd tune`) that measures every proposed filter: attack variants hidden versus corpus alerts removed |
| The analyst knows what to do | Triage and response cards, closure notes (benign or false positive) and an escalation note, generated from each detection's contract (L1 / L2 / IR actions, risk model, evidence, containment), and a DFIR playbook for every technique |
| The offensive test and the rule agree | Every red test's sample event **is** one of its detection's true positives, and CI proves it matches |
| The first touch of a decoy is an alert, and the decoys stay real | **RASD-Deceive** (`rasd deceive`): seven decoys - honey accounts, a honey SPN account, honey credential files, a decoy host - defined once in an inventory and read by four Sigma rules that pass every proof above (each proven to fire on every documented way of touching a decoy and to stay quiet on everything else). `--check` fails the build when the inventory, a rule, its tests, its red test or the decoy host's configuration drift apart; `--rename` adopts your own identities everywhere so the proofs are about your decoys, not the examples ([DECEPTION](DECEPTION.md)) |
| It fires on attack telemetry recorded by others | **Public dataset replay** (`rasd datasets`): files from three public sources (Splunk Attack Data, OTRF Security-Datasets, EVTX-ATTACK-SAMPLES), each pinned to a commit and a SHA-256, replayed through every detection and correlation. Every alert is either the recorded attack or explained in the catalog (the labs' test harness, other benign activity, or false positive); every record is counted once, with repeats inside a file and copies between files found and declared; every documented limit is re-checked on each run; and the applied tunings are measured on the labs' background activity. It showed rules blind to real attacks - Invoke-Mimikatz and PPLdump behind the LSASS rule's System32 filter, a bare `cmd.exe` service binary, three rundll32 proxy exports, a Run value pointing into `C:\Windows\Tasks`, sprays over guessed account names - and each fix is proven on the public events, so those rules' results there are marked in-sample. Public data is not lab evidence: it does not raise a detection's maturity |
| It can be proven in a real environment | `rasd evidence` joins a lab run, its telemetry export and optional SIEM alerts, and writes evidence only when the rule really fired on an event bound to that run (host or client address, time window, run marker) - with the SHA-256 of every input. The status line of the [README](../README.md) says how many detections have one, and the runs that may be public are kept in [purple/lab_runs](../purple/lab_runs/README.md), where every build recomputes their evidence |
| Nothing is overstated | Maturity levels and both scores are computed; a contract cannot claim more than the repository proves. Without lab evidence a detection stops at **SIEM-Ready** (deployable, not validated), and the Operational Score counts only what a committed lab run shows |
| The evidence survives the intruder, or the attempt to remove it is seen | **RASD-Trace** (`rasd trace`): the artifacts each technique writes, the questions each one answers (did it run, when, who, how, from where) and the anti-forensic actions that destroy or blind them are written down once, with what every action itself leaves behind. An exhaustive search over every sequence of those actions around the technique gives each detection and question a verdict: out of reach, evident (every sequence that removes the answer raises a RASD alert) or exposed, with the cheapest quiet sequence shown. A trace that names a rule is replayed through the engine in CI, the unread traces are ranked into the next rules to write, and `--lost` tells an investigation what can still be proven once logs are gone. Documented behaviour, pending the same lab runs as everything else ([TRACE](TRACE.md), [results](../dfir/trace/README.md)) |
| A rule that stayed quiet is evidence, or it is said why not | **RASD-Silence** (`rasd silence`): for every detection on every host of an export, the quiet is **attested** only between two records that show the sensor recording, with every record between them present (the channel's record numbers are consecutive) and none saying the sensor stopped, changed or was emptied. Any other quiet is **unattested**, with its reason and what to turn on. Record numbers missing, a channel cleared, a logging service started with no stop before it, and a host that another host kept recording while its own channels said nothing, are listed as breaks in the record. A host that was shut down or asleep is not counted either way. `--certificate` writes the result with the SHA-256 of every input and what it does not say; with no export, on Windows, the host's own event logs are read ([SILENCE](SILENCE.md)) |
| A green cell is a wall, or the way through it is shown | **RASD-Blindpath** (`rasd blindpath`): a coverage map says which techniques have a rule; this says how far an intruder gets while stepping only on those techniques. From each origin to each target of an export it walks the legs of an intrusion (run code, take credentials, move in, run code on the target) and calls a behaviour **unseen** on a host only on proof: the export holds no record of the sensor its rules read from that host (the verdict of `rasd silence`), or one sequence of events of the behaviour, replayed through every rule and correlation, raises no alert. The events are a variant `rasd certify` shows slipping past the rule, or a correlation's own true positives paced one under its threshold. A route with every leg open is **unseen end to end**; any other names the first leg that sees it and what that hold rests on. The plan is the fewest changes, a variant closed in a rule or a sensor turned on on a host, after which every route is seen by each leg in turn, found by exact search and walked again once applied. Decoys are shown as tripwires and never counted, and a variant the pipeline or the target decides is never walked ([BLINDPATH](BLINDPATH.md)) |
| You know what to do next, and why that first | **RASD-Agent** (`rasd advise`): every measurement above turned into ranked findings with the evidence and the exact next step, for the analyst, the engineer, the purple team and the executive: the lab wave that validates the most detections, the known gap with its fix, the boundary no test pins, the tuning that is safe on the corpus but contradicts a behaviour spec, the next rule the tracked groups press on. Each finding has a stable id; what you decide about it is remembered and ranks the counsel, and an accepted finding that disappears counts as resolved. `--logs` reads your own telemetry, `--explain` reads an alert with the contract's guidance and the deception chain, `--propose` drafts the change and verifies it with the same gates before writing it, `--apply` copies it in and runs them. A language model is optional and everything it writes is gated ([AGENT](AGENT.md), [the counsel on this build](../agent/ADVICE.md)) |
| The library grows between releases, and what grew alone is never mistaken for what was reviewed | **RASD-Agent's lane** (`rasd grow`): the queue is the whole ATT&CK Enterprise matrix, read from MITRE's own release, minus what the core and the lane already cover, the techniques used by the most documented groups first. For each one a language model drafts a rule with its tests, and the draft is kept only when every gate accepts it: the engine, the field vocabulary of the log source, every attacker variation of the fuzzer, the events the repository records as benign, KQL and SPL parity. The proof is computed, not asked for: the tests a rule mutant survives are built from the exact automata, and a part no event can tell apart is removed, so no mutant survives. Candidates live in [`detect/candidates`](../detect/candidates/README.md), beside the core and outside every number above; each run proves them again and retires the one that no longer passes; a scheduled workflow publishes the lane only behind the full pipeline and only its own files. A person promotes a candidate into the core; nothing else needs one ([GROW](GROW.md)) |
| Every detection is still being fed | **RASD-Health** (`rasd health`): an export of today's telemetry against a baseline, and a verdict for every detection: healthy, degraded, blind or nothing to compare. A host that stopped sending, a volume that fell, a field that was renamed, command lines cut short, events that arrive after the scheduled search has looked, a search the scheduler skipped: each is reported once, with the detections it takes with it. The same checks are generated as SPL and KQL watchdog searches from what the library's own rules read ([HEALTH](HEALTH.md)) |
| The lab evidence still holds for today's rule | **Recomputed evidence** (`rasd evidence --check`): the raw files of a lab run that may be public are kept in the repository, and on every build each `evidence.md` that cites one must be, byte for byte, what `rasd evidence` writes from it with today's rules. A rule edited until it no longer fires on its run loses its evidence in the same build ([lab runs](../purple/lab_runs/README.md)) |
| What the agent drafted is never mistaken for what a person approved | **Governance** (`rasd review`): a person's verdict on a candidate is recorded against the SHA-256 of the rule text, in a ledger the unattended run may not change; only an approved text can be promoted into the core; every decision of the agent or of a person is one line of a hash-chained audit trail; and hostile drafts, written as a model that was talked into them would write them, are refused by the gates in the tests ([GOVERNANCE](GOVERNANCE.md)) |
