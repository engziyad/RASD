## Objective

Create two scheduled tasks the way intruders do - with schtasks.exe and a cmd /c action in %TEMP%, and with Register-ScheduledTask and an inline action in $env:TEMP - and prove each one fires its own detection. Neither task ever runs: the schtasks trigger is 23:59 once, the PowerShell trigger is a year away, and both are deleted by cleanup.

## Prerequisites

- Windows 10/11 or Windows Server lab VM with Sysmon (Event ID 1) installed
- Audit Other Object Access Events (success) for Security 4698, which records the task XML

## Safety notes

- Runs only with -LabConfirmed on a disposable lab VM you own
- The schtasks action is cmd /c echo &lt;marker&gt; to a text file in %TEMP%; the PowerShell action points to a file that does not exist
- Both tasks are named after the run marker, so cleanup can only remove what this test created

## Execution

1. Step 1: schtasks /create /tn &lt;marker&gt; /sc once /st 23:59 /f /tr "cmd /c echo &lt;marker&gt; &gt; %TEMP%\\&lt;marker&gt;.txt"
2. Step 2: powershell -NoProfile -Command "Register-ScheduledTask -TaskName &lt;marker&gt;\_ps ... -Action (New-ScheduledTaskAction -Execute $env:TEMP\\&lt;marker&gt;.exe)"
3. collect\_artifacts.ps1 exports both task definitions as XML before cleanup deletes them

## Cleanup

- Deletes the task &lt;marker&gt; (schtasks /delete)
- Unregisters the task &lt;marker&gt;\_ps (Unregister-ScheduledTask)
- Removes %TEMP%\\&lt;marker&gt;.txt if the schtasks action ever ran

**Verification:** Neither task can be queried any more and the marker file does not exist

Script: [`cleanup.ps1`](cleanup.ps1) (exit code 0 only when the host is verified clean).
