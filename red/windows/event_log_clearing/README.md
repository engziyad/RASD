# Event log clearing (dedicated test log, optional Security log)

## Objective

Clear an event log with wevtutil the way intruders do and prove all three log-clearing detections fire: the wevtutil process, the System 104 record of the clear and - only when you opt in - the Security 1102 record. The default step clears a log this test creates for itself, so no real evidence is ever destroyed.

## Prerequisites

- Windows 10/11 or Windows Server lab VM, elevated PowerShell (Windows PowerShell 5.1 for New-EventLog)
- Sysmon (Event ID 1) installed; System and Security logs forwarded to the SIEM

## Safety notes

- Runs only with -LabConfirmed on a disposable lab VM you own
- The default step creates a log named R&lt;hex&gt; (the marker's random part; classic log names are unique on 8 characters), writes one entry and clears only that log
- The Security-log step runs only with -IncludeSecurityLogClear, backs the log up with wevtutil /bu first, and refuses to overwrite an existing backup
- Forward logs to the SIEM before using the Security-log step; the local Security log is emptied

## Execution

1. Step 1: New-EventLog -LogName R&lt;hex&gt; -Source &lt;marker&gt;; Write-EventLog ...; wevtutil cl R&lt;hex&gt;
2. Step 2 (opt-in): wevtutil cl Security /bu:%TEMP%\\security-before-clear-&lt;marker&gt;.evtx
3. collect\_artifacts.ps1 saves the 104 (and 1102) records of the clear as JSON
4. cleanup.ps1 removes the test log; the Security backup stays on disk as evidence
