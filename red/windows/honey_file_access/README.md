## Objective

Do what a search for credentials in files ends with: open the decoy spreadsheet of service accounts that RASD-Deceive plants in a Passwords folder, on the lab host that holds it, and prove that the host's 4663 (ReadData through the decoy's audit entry) fires the honey file rule. The file is read, not changed; its contents are the lures of the other decoys.

## Prerequisites

- Windows lab host (workstation or file server) with the decoy files deployed on it
- deceive\\Deploy-RasdDecoys.ps1 -LabConfirmed -Files: creates C:\\Shares\\IT\\Passwords\\service\_accounts.xlsx (and the other two decoys), sets the audit entry on each, and enables the File System audit subcategory (Success)
- Audit policy: Object Access &gt; Audit File System = Success; the step warns when it is off
- RASD\_DECOY\_ROOT when the decoys live under another root than C:\\Shares

## Safety notes

- Runs only with -LabConfirmed on a machine its owner marked as a lab (red/lab/README.md, Lab guard)
- The decoy is read once and never changed; the step refuses when the file is missing or carries no audit entry
- The decoy files hold decoy credentials only (deceive/decoys.yml); nothing real is written into them

## Execution

1. Invoke-RasdEmulation.ps1 -Test honey\_file\_access -LabConfirmed
2. The step checks the decoy's audit entry and the audit policy, then reads the file once (System.IO.File ReadAllBytes)
3. collect\_artifacts.ps1 saves the decoy's audit entries and the File System audit policy
4. Export-LabTelemetry.ps1 -LogName Security -EventId 4663 -Since &lt;start&gt; -OutFile lab-export.jsonl, then rasd evidence
