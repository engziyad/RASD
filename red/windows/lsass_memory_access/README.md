## Objective

Dump LSASS memory with the built-in comsvcs.dll MiniDump export through rundll32 - the living-off-the-land technique seen in many intrusions - and prove that both the process access to LSASS and the rundll32 command line fire their detections. The dump is hashed and deleted immediately; it is never copied or parsed.

## Prerequisites

- Windows 10/11 or Windows Server lab VM, elevated PowerShell
- Sysmon with a configuration that logs process access to lsass.exe (Event ID 10)
- In this lab only: LSA protection (RunAsPPL) off and endpoint protection set to allow the test - both block this attack on hardened hosts, which is the point

## Safety notes

- Runs only with -LabConfirmed -IncludeCredentialAccess on a disposable lab VM you own
- Use a VM whose credentials exist nowhere else; an LSASS dump contains them
- The dump goes to C:\\Windows\\Temp\\&lt;marker&gt;.dmp (MiniDump cannot take a quoted path, so never a profile path with spaces), is hashed by collect\_artifacts.ps1 and deleted by cleanup.ps1

## Execution

1. rundll32.exe C:\\Windows\\System32\\comsvcs.dll, MiniDump &lt;lsass PID&gt; C:\\Windows\\Temp\\&lt;marker&gt;.dmp full
2. collect\_artifacts.ps1 records the dump's size and SHA-256 (not the dump itself)
3. cleanup.ps1 deletes the dump and confirms it is gone
