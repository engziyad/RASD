## Objective

Log in as one lab account and request objects that belong to other users by walking a small range of IDs. Every foreign object served is a broken object-level authorization finding, and the sequential-ID pattern it leaves in the logs is what a detection for data scraping would key on.

## Prerequisites

- A lab copy of the application on localhost or a private address (for example OWASP Juice Shop)
- A lab test account, given to the test as RASD\_LAB\_EMAIL / RASD\_LAB\_PASSWORD environment variables
- Web server or reverse-proxy access logs collected

## Safety notes

- Runs only with --lab-confirmed; refuses any target that resolves to a public address
- Read-only GET requests for at most 20 object IDs (default 5)
- Credentials are read from the environment, never from the command line

## Execution

1. export RASD\_LAB\_EMAIL=alice@lab.local RASD\_LAB\_PASSWORD=...
2. python3 red/run\_red.py --test idor\_testing --lab-confirmed --target http://127.0.0.1:3000
3. The test logs in, notes the account's own basket ID, and requests baskets 1..5
