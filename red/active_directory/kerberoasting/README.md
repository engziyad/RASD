## Objective

Request a Kerberos service ticket for a service account's SPN from an ordinary domain user, as Kerberoasting tools do before cracking the ticket offline, and prove the domain controller's 4769 event fires the RC4 Kerberoasting detection. The ticket stays in the session's cache; nothing is exported and nothing is cracked.

## Prerequisites

- Domain-joined lab workstation and a lab domain controller
- A lab service account with an SPN set to RC4 only: Set-ADUser &lt;account&gt; -Replace @{'msDS-SupportedEncryptionTypes'=4}. Unset or with AES bits, current DCs issue an AES ticket (0x12) and the rule correctly stays silent; the step reads the attribute and refuses to run when it is not RC4-only, when no account holds the SPN, or when AD cannot be read
- Restore the account's msDS-SupportedEncryptionTypes after the lab
- DC audit policy: Account Logon &gt; Audit Kerberos Service Ticket Operations = Success

## Safety notes

- Runs only with -LabConfirmed and an explicit -Spn from your lab domain
- One ticket request; the ticket is not exported, saved or cracked
- The step runs klist purge in its own logon session first; the new ticket expires with the session

## Execution

1. Invoke-RasdEmulation.ps1 -Test kerberoasting -LabConfirmed -Spn MSSQLSvc/sql01.lab.local:1433
2. The step purges the session's Kerberos ticket cache (a cached ticket would be reused and the DC would log nothing), then requests the ticket with System.IdentityModel KerberosRequestorSecurityToken
3. collect\_artifacts.ps1 saves klist output, which shows the ticket's encryption type
4. Export the domain controller's Security log too (Export-LabTelemetry.ps1 -LogName Security -EventId 4769) and pass both exports to evidence
