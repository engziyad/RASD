# Password spray simulation with a password that cannot be right

## Objective

Produce the telemetry of a password spray - one failed authentication for each of many accounts, from one source, within seconds - without any chance of guessing a password: the password is a fresh random 40-character value. The test proves the domain controller records the failures and that the password-spray correlation fires on the burst.

## Prerequisites

- Domain-joined lab workstation and lab domain controller
- A text file of 9 or 10 lab test accounts (one sAMAccountName per line) - never real users. The correlation alerts at 5 distinct accounts per source in a 10-minute window, and 9 or more always alert whatever the window alignment
- DC audit policy: Account Logon &gt; Audit Kerberos Authentication Service = Failure (4771), Audit Credential Validation = Failure (4776), Logon/Logoff &gt; Audit Logon = Failure (4625)

## Safety notes

- Runs only with -LabConfirmed and an explicit -UserList of lab test accounts
- Exactly one attempt per account, at most 10 accounts per run
- Refuses to run when the domain lockout threshold is 1 or 2, and skips any account whose own threshold (domain or fine-grained policy) is 1 or 2 or whose badPwdCount is within one failure of it
- badPwdCount is kept per domain controller, and fine-grained policies are visible only to accounts allowed to read them (run as a lab admin for a complete check): use lab test accounts only
- The password is random and generated per run, so no attempt can succeed

## Execution

1. Invoke-RasdEmulation.ps1 -Test password\_spray\_simulation -LabConfirmed -UserList .\\lab-users.txt
2. The step reads the domain lockoutThreshold, each account's resultant fine-grained policy and badPwdCount, and skips accounts one failure could lock
3. For each account it attempts one LDAP bind with the random password
4. Export the DC Security log (Export-LabTelemetry.ps1 -LogName Security -EventId 4768,4771,4776,4625) and pass it to `rasd correlate --logs` and `rasd evidence`
