# DFIR artifacts · Honey account use - try the decoy credential, request the decoy's service ticket

| Artifact | Location | How to collect | Why it matters |
|---|---|---|---|
| Decoy attributes at run time | Active Directory (badPwdCount, lastLogon, servicePrincipalName, description) | `collect_artifacts.ps1 saves decoy-accounts.json` | Shows the decoys were in place as the inventory describes them when the events were produced |
| Ticket cache | Workstation logon session | `klist` | Shows the honey SPN's ticket and its encryption type on the client, if the KDC issued one |
| Authentication events for the decoy | DC Security log | `Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4771,4776,4625,4768} on the DC, filtered on the decoy's name` | Every attempt against the decoy, with the source address or workstation |
| 4769 for the decoy SPN | DC Security log | `Get-WinEvent -FilterHashtable @{LogName='Security'; Id=4769} on the DC, filtered on ServiceName` | Who requested the decoy's ticket, from where, with which encryption type |

[`collect_artifacts.ps1`](collect_artifacts.ps1) collects what it can of these before cleanup runs (see the script for exactly which); the runner records the SHA-256 of every collected file in the results, so the evidence can be verified later.

Collect before cleaning up: the cleanup script removes what the test created, which can include artifacts listed here ([cleanup](README.md#cleanup)).
