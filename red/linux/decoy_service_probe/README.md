## Objective

Touch the decoy host the way reconnaissance and a credential guess do: open a TCP connection to its SSH port, as a port scan or an SSH client does, and post one login attempt to its web portal with the run marker as the user name, and prove that the decoy's records fire the decoy service rule. The marker in the recorded user name binds the record to this run.

## Prerequisites

- Linux lab host with bash and curl, on the same network as the decoy
- The decoy host running OpenCanary with deceive/opencanary/settings.json (node\_id lab-canary-01, ssh and http enabled), and its log forwarded to the SIEM or copied out for evidence
- --target: the decoy portal's URL (http://10.0.0.40 in the shipped inventory); the lab guard refuses a public address

## Safety notes

- Runs only with --lab-confirmed on a disposable lab host you own, marked by /etc/rasd-lab-host (red/lab/README.md, Lab guard)
- One TCP connection, opened and closed without sending data, and one HTTP POST with a made-up credential; nothing is left anywhere
- The target must be a private lab address; the runner refuses public ones

## Execution

1. python3 red/run\_red.py --test decoy\_service\_probe --lab-confirmed --target http://10.0.0.40
2. On the decoy host: cp /var/tmp/opencanary.log canary-export.jsonl, copy it to the analysis host, then rasd evidence --results &lt;results&gt;/emulation-results.json --logs canary-export.jsonl
3. bash -c 'exec 3&lt;&gt;/dev/tcp/&lt;decoy&gt;/22' then curl --data-urlencode username=&lt;marker&gt; --data-urlencode password=probe http://&lt;decoy&gt;/index.html
