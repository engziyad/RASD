# RASD Splunk apps

Generated by `tools/splunk_app.py` on every build; do not edit by hand.

| App | Install on | What it does |
|---|---|---|
| [`rasd/`](rasd/) | Splunk Enterprise / trial (search head and indexer) | `sysmon`, `wineventlog`, `linux`, `web`, `rasd_alerts` indexes, `Provider_Name` extraction, one scheduled alert per detection and per correlation, three alert export reports |
| [`rasd_forwarder/`](rasd_forwarder/) | Universal Forwarder on each Windows lab VM and the lab DC | Sysmon, Security, System and PowerShell logs as XML into those indexes |
| [`rasd_forwarder_linux/`](rasd_forwarder_linux/) | Universal Forwarder on a Linux lab host | Sysmon for Linux into `linux`; the lab web application's access log into `web` (disabled until you set its path) |

Prerequisites on Splunk: the **Splunk Add-on for Microsoft Windows** and the **Splunk Add-on for Sysmon** (field extractions such as `EventCode`, `CommandLine`, `TicketEncryptionType`), the **Splunk Add-on for Sysmon for Linux** on the search head and the Linux forwarder, and receiving enabled on port 9997. The web access log uses Splunk's built-in `access_combined` extractions (`clientip`, `method`, `uri_path`, `status`).

Install: copy each folder into `$SPLUNK_HOME/etc/apps/` (on a Windows forwarder: `C:\Program Files\SplunkUniversalForwarder\etc\apps\`; on a Linux forwarder: `/opt/splunkforwarder/etc/apps/`) and restart Splunk. The full lab procedure is in [red/lab](../../red/lab/README.md).

## Alerts

Each alert runs every 5 minutes over one 5-minute slice that closed 5 minutes earlier (`-10m@m` to `-5m@m`): consecutive runs tile time and `realtime_schedule = 0` makes Splunk catch up a run it skipped, so an event is alerted exactly once, and up to 5 minutes of indexing delay never drop one (events indexed later than that are missed by the alert, not by `rasd replay`). It fires once per host in the slice (digest mode off), so two hosts are two alerts. Its base search is the generated query in [`queries/spl`](../spl/), proven equivalent to the tested rule by `rasd parity`; the saved search appends a per-host summary row only for reliable alert export.

## Correlation alerts

A correlation alert counts per window. It runs once per window length over the last two windows plus 3 minutes (indexing delay) and keeps only the most recent window that is complete inside that range (`addinfo` and one `where`): consecutive runs tile time, so every window is reported whole by exactly one run, with the search head in UTC or any fixed-offset time zone (where it observes daylight saving, a window can be dropped or repeated at the transitions). `realtime_schedule = 0` makes Splunk catch up a run it skipped. Events indexed more than 3 minutes late are missed by the alert (not by `rasd correlate --logs`). It alerts once per result row - one window and one group (for example one spraying source) - and its search starts with the generated query in [`queries/spl/correlations`](../spl/correlations/), proven by `rasd correlate` to return exactly the engine's alerts.

| Saved search | Correlation | Condition | Schedule | Severity |
|---|---|---|---|---:|
| `RASD - T1110.003_password_spray_burst` | Password Spray - One Source Failing Authentication for Many Accounts | >= 5 distinct TargetUserName per IpAddress in 10m windows | `*/10 * * * *` | 5 |
| `RASD - T1190_object_id_enumeration` | Object ID Enumeration - One Client Walking Single-Owner Objects | >= 3 distinct cs-uri-stem per c-ip in 1m windows | `*/1 * * * *` | 5 |
| `RASD - T1558.003_kerberoasting_volume` | Kerberoasting - One Client Requesting Tickets for Many Service Accounts | >= 5 distinct ServiceName per IpAddress in 10m windows | `*/10 * * * *` | 5 |
| `RASD - T1595.003_api_auth_probing` | API Probing - One Client Rejected on Many Distinct Paths | >= 5 distinct cs-uri-stem per c-ip in 5m windows | `*/5 * * * *` | 4 |

Every alert also writes one event to the `rasd_alerts` index (Log Event alert action). A detection's alert search is the proven rule query plus a lab-only summary per host (`stats count`, first and last event time `by` detection and host), so the export gets a deterministic host even when Splunk result tokens differ between deployments. A correlation's search is its proven query plus the window filter and three `eval` fields (detection id, alerting group, event count): its rows already carry the window, the counts and the first and last event.

## Alert export for `rasd evidence`

Run one of these reports over the lab window, export the result as CSV and pass it to `rasd evidence --siem-alerts`. Each row is one alert: `_time` (when it fired) and `ss_name` (which carries the detection id). They read three independent sources, so a Splunk where one of them is restricted still has the others.

| Report | Source | Use | Notes |
|---|---|---|---|
| **RASD - alert export** | `index=rasd_alerts` | **Preferred** | Carries the alerting `host`, which evidence checks against the lab host |
| **RASD - alert export (audit)** | `index=_audit action=alert_fired` | Acceptable fallback | No host: the alert is matched by name and time only; needs a role that can search `_audit` |
| **RASD - alert export (scheduler)** | `index=_internal sourcetype=scheduler` | Acceptable fallback | Scheduled runs that returned results, no host; needs a role that can search `_internal` |

On the first lab run, check that the host really reaches `rasd_alerts`: `index=rasd_alerts | table _time rasd_alert alert_host alert_hosts first_event last_event`. An empty `alert_host` means the alert's results had no usable host field; the export still works, matched by name and time like the fallbacks. For a correlation, `alert_host` is its first group-by value - the client address for every correlation in this repository.

Each alert reads a slice that closed 5 minutes earlier and runs every 5 minutes, so the SIEM latency `rasd evidence` reports includes 5 to 10 minutes of schedule wait on top of the indexing delay; the evidence file shows both parts. A correlation alert waits for its window to close, so its latency includes up to two window lengths plus 3 minutes.
