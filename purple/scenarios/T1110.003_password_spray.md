# Purple Scenario: Password Spraying (T1110.003 Brute Force: Password Spraying)

## Objective
Validate that one failed authentication for each of 9 lab accounts, from one workstation within seconds, is logged by the domain controller and raises the password-spray correlation - an aggregate detection no single-event rule can express.

## Red
Run `password_spray_simulation -UserList <9 or 10 lab accounts>`: one LDAP bind per account with a random 40-character password generated for the run, so no attempt can succeed. Accounts one failure away from lockout are skipped.

Test folder: [`red/active_directory/password_spray_simulation`](../../red/active_directory/password_spray_simulation/) · expected telemetry: [expected_telemetry.md](../../red/active_directory/password_spray_simulation/expected_telemetry.md)

## Telemetry
- DC Security 4771 - Kerberos pre-authentication failed, Status 0x18, TargetUserName, IpAddress of the workstation (as `::ffff:<IP>`)
- DC Security 4625 - failed network logon with SubStatus 0xC000006A when the bind falls back to NTLM (IpAddress without `::ffff:`)

## Detect
- [`T1110.003_password_spray_burst`](../../detect/correlations/T1110.003_password_spray_burst/) - Sigma correlation: 5 or more distinct accounts per client address in a 10-minute window; 9 or more always alert, whatever the window alignment

Run the full gate for this correlation:

```bash
rasd correlate --filter T1110.003 -v
rasd correlate --logs dc-export.jsonl
```

## DFIR
Playbook: [password_spray.md](../../dfir/playbooks/password_spray.md). Collect:
- The failure burst (4771 / 4625) from the source for the window
- Successful logons (4768 / 4624) from the source after the burst
- Lockouts (4740) caused by the spray
