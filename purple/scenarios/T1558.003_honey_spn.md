# Purple Scenario: Honey SPN Ticket Request (T1558.003 Steal or Forge Kerberos Tickets: Kerberoasting)

## Objective
Validate that a service ticket request for the decoy service account - requested as every Kerberoasting tool requests each SPN it enumerates, with whatever encryption type the KDC picks - is logged by the domain controller and fires the honey SPN detection. This is the control for the gap the RC4 rule documents: AES roasting of a few accounts.

## Red
Run `honey_account_use`: the second step reads `svc_sqlreport`'s servicePrincipalName from the directory, purges the session's ticket cache and requests one service ticket through KerberosRequestorSecurityToken; nothing is exported or cracked.

Test folder: [`red/active_directory/honey_account_use`](../../red/active_directory/honey_account_use/) · expected telemetry: [expected_telemetry.md](../../red/active_directory/honey_account_use/expected_telemetry.md)

Decoys must be deployed first: `deceive\Deploy-RasdDecoys.ps1 -LabConfirmed -Accounts` ([inventory](../../deceive/decoys.yml)).

## Telemetry
- DC Security 4769 - ServiceName `svc_sqlreport`, TicketEncryptionType 0x12 or 0x17, Status 0x0 (or a refusal), IpAddress of the workstation

## Detect
- [`T1558.003_honey_spn_ticket_request`](../../detect/detections/T1558.003_honey_spn_ticket_request/) - rule, tests, mutation tests, behaviour proof, KQL and SPL

The RC4 rule [`T1558.003_kerberoasting_rc4_tgs`](../../detect/detections/T1558.003_kerberoasting_rc4_tgs/) fires on the same event only when the KDC issues RC4; the decoy fires either way, which is the point of this scenario. The volume correlation stays silent on one ticket, as its scenarios prove.

Run the full gate for this detection:

```bash
rasd test --filter T1558.003_honey
rasd prove --filter T1558.003_honey
rasd certify --filter T1558.003_honey
rasd parity --filter T1558.003_honey
rasd deceive --check
```
