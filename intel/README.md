# RASD-Intel: CTI to Detection

RASD-Intel turns threat reports and ATT&CK knowledge into detection opportunities, hunts and SOC actions - and ties each of them back to the offensive tests and detections that already exist in this repository, so intelligence lands as work, not as a summary nobody acts on.

## CTI to Detection Workflow

```text
CTI Report
   ↓
Extract Behaviors
   ↓
Map to ATT&CK
   ↓
Identify Data Sources
   ↓
Create Detection Opportunities
   ↓
Build Sigma / SPL / KQL
   ↓
Prove with Tests
   ↓
Add Triage and Response
   ↓
Measure Coverage
```

| Folder | Contents |
|---|---|
| [`templates/`](templates/) | CTI report review, TTP mapping, detection opportunity, intel-to-detection card |
| [`mappings/`](mappings/) | Technique map, data sources, detection ideas, actor tradecraft map (generated where marked) |
| [`reports/`](reports/) | A worked example: the synthetic lab-day intrusion analysed with the templates |
| [`outputs/`](outputs/) | Detection opportunities, hunting ideas and SOC actions produced by the analysis; the [detection backlog](outputs/detection_backlog.md) ranks the open gaps |

**ATT&CK version.** RASD keeps legacy ATT&CK v18 aliases for compatibility, while primary mappings follow ATT&CK v19.2. ATT&CK v20 (13 October 2026) changes no ID or tactic of the techniques RASD maps: its release notes touch PowerShell (T1059.001, a description update), Service Execution (T1569.002) and Disable or Modify Tools (T1685, a new sub-technique), none of them a remapping. ATT&CK v19 split Defense Evasion into Stealth (TA0005, the renamed tactic) and Defense Impairment (TA0112), and moved Clear Windows Event Logs from T1070.001 to [T1685.005](https://attack.mitre.org/techniques/T1685/005/). The three log-clearing detections are named and tagged T1685.005 with the `defense-impairment` tactic; every other Defense Evasion tag became `stealth` (the rundll32 rule, and the related T1027 on the encoded PowerShell and Linux shell rules). [`intel/mappings/attack_v18_aliases.yml`](mappings/attack_v18_aliases.yml) keeps every v18 identifier resolvable: `rasd test --filter T1070.001` still runs those detections, and the generated KQL and Defender queries and the Splunk saved searches name the v18 technique, so content built on T1070.001 still finds them.

`mitre_techniques.md`, `data_sources.md`, `actor_tradecraft_map.md` and `outputs/detection_backlog.md` are generated by `tools/chain.py` from the detections, the red tests, [`mappings/actors.yml`](mappings/actors.yml) and [`mappings/backlog.yml`](mappings/backlog.yml); edit those sources, never the generated files. CI fails when a red test documents a gap the backlog does not list, or when the backlog lists a technique a detection now covers.
